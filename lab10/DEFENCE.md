# Захист лабораторної роботи №10

Аудит документації, паспорт SDD / ISD / ADR, краш-тест розпаду і пакет передачі

Гілка `testing/lab10`. Паспорт `80c9cac`. FAIL `22a20df`. PASS `e8f1346`. Звіт: `lab10/REPORT.md`. Розділи «Діагноз», «Наслідки ADR» і «Вердикт передачі» в звіті вже переписані. На захисті проговори їх уголос. Цифри нижче ті самі.

## 1. Мета

Порахувати, які документи Relativa ще описують систему, а які залишились від заглушок. Зібрати паспорт: як влаштовано, де запущено, чому база і черга саме такі. Зламати актуальність одним комітом без правок документів і повернути її другим. Показати, що новій людині досить README, SDD і ISD, щоб підняти стек.

## 2. Що зроблено

Зріз віку — 2026-11-22, команда `git log -1 --format=%cs`. Core має 100 комітів на 1 коміт `Core/README.md`. Graph — 43 на 1. Migration — 61 на 1. ML — 24 на 1. Gateway — 23 на 1. Client — 113 на 1. Це більше за поріг 20. README цих сервісів досі описують порожню модель, заглушку хаба, заглушку JWT, stub ML і `entrypoint.sh`. На них стоїть банер deprecated.

`ARCHITECTURE.md` і `DATABASE.md` молодші за 30 днів. 13 комітів Graph після архітектурного гайда — фікстури лабораторних, не новий сервіс.

Паспорт: `docs/sdd.md` (C4, компоненти, фрагмент EAV, контракти), `docs/isd.md` (Compose, CI, RTO 4 години, RPO 24 години для Postgres, факт — дампа немає), ADR 0001 і ADR 0002. README отримав онбординг із п'яти кроків замість посилання на відсутній `docs/USER-GUIDE.md`.

## 3. Покроково

FAIL додає `GET /api/v1/operator/digest` у процесі шлюзу і ставить `graph` у залежність від старту контейнера `ml`. Документи не чіпає. На цьому коміті ISD ще каже, що Graph не чекає ML. SDD не знає типу `OperatorDigestEndpoints`. README не називає маршрут.

Лічильник: `Gateway/src` 21 на паспорті, 22 на FAIL, комітів SDD на FAIL досі 1. Після PASS комітів SDD 2, комітів `Gateway/src` після останнього з них — 0. Вік у днях не змінювався, бо всі три коміти в один день. Розклад видно по тому, який коміт останній у файлі.

Перевірка з кореня:

```text
git branch --show-current
git log -4 --oneline
git show --stat 22a20df
git grep -n "не чекає ML" 22a20df -- docs/isd.md
git grep -n "operator-digest" HEAD -- README.md docs/sdd.md
```

## 4. Висновок

Продуктовий документ живе з кодом. Процесний документ, звіт лабораторної, лишається свідченням того дня. SDD відповідає на «хто з ким говорить». ISD відповідає на «в якому порядку підняти і скільки даних можна втратити».

Після PASS операційну карту можна віддати іншій людині. Колонки бази лишаються в `DATABASE.md`. Gateway, Migration і ML усе ще авторськи важкі: наступна зміна там іде з другим читачем.
