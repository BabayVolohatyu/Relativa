# Протокол CCB, 2026-11-22

- RFC: [RFC-001](rfc-001.md)
- Засідання: 2026-11-22T21:45:00Z
- Кворум: чотири ролі з чотирьох. Ролі виконав один автор гілки, аргументи розведені по гранях ризику, не злиті в одну фразу «можна»

| Роль | Питання, яке ця роль закриває | Позиція |
|---|---|---|
| Архітектор | Чи лишається одна база ADR-0001 і чи не з'являється другий мігратор | Так. Новий ADR не відкриваємо |
| QA | Чи є регресія HTTP і чи достатньо збірки Migration | HTTP не змінюється. Умова: збірка Migration і зелений drill |
| SRE | Чи можна відновити том і чи не знесе truncate живі дані | Умова: entrypoint не робить DROP без `RELATIVA_TRUNCATE_I_HAVE_A_DUMP=yes`. Відновлення основної бази цим RFC не автоматизується |
| Продуктовий власник | Чи варте вікно цієї дати | Так для стенда. У прод не виносимо, доки немає копії поза машиною |

## Рішення

Погоджено з умовами.

1. Drill пише лише в `relativa_drill` і завершується кодом 0 до того, як RFC перейде в Closed.
2. `DROP DATABASE` основної бази без явного прапора дампа дає код виходу 1.
3. `docs/api/openapi.yaml` не змінюється.
4. CHANGELOG отримує рядок про гарду truncate.

Термін умов: той самий день, 2026-11-22, коміт PASS.

## Регламент CCB

Засідання — раз на тиждень, або в день нормальної чи термінової зміни, якщо тиждень уже закритий. RFC подається файлом у `docs/operations/` зі станом не нижче Assessment і з матрицею семи рівнів. Стандартна зміна (правка тексту без поведінки) на засідання не виноситься.

Change freeze: якщо `docs/slo.yaml` фіксує, що за 30 діб вичерпано `error_budget_minutes` хоча б одного індикатора, CCB відхиляє нормальну і стандартну зміну, яка не є роботою зі стабільності. Термінова зміна, що зупиняє втрату даних, лишається допустимою. Заморозка спадає за правилом `error_budget_policy.lift` у тому ж файлі.
