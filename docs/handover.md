## Онбординг

1. Прочитати в `README.md` розділ What is Relativa: для кого продукт і що він уже робить.
2. Скопіювати `.env.example` у `.env`. Файл `.env` не комітити.
3. З кореня виконати `docker compose up --build -d`. Відкрити http://localhost:3000 і зареєструватися. Перевірити http://localhost:8080/health (`status` = `ok`).
4. Без токена відкрити http://localhost:8080/api/v1/operator/digest. У тілі `kind` = `operator-digest`, у `includes` — `openDeals`, `highRiskDeals`, `pendingInvitations`. Чисел угод там немає. Створити організацію і робочий простір у UI. Схему вже поклав контейнер `migration`.
5. Карта сервісів і контракти — `docs/sdd.md`. Порядок підняття, імена змінних, RTO/RPO — `docs/isd.md`. Якщо сервісний README суперечить цим двом, правий паспорт.

## Вердикт

Після PASS система в стані, в якому її можна передати: новий розробник проходить п'ять кроків вище і не потребує автора, щоб підняти стек, назвати контейнери і показати контракт digest. Це і є Ready to Handover для операційної карти.

Не передано «все, що автор пам'ятає про кожну колонку». Для колонок є `DATABASE.md` (останній коміт 2026-10-25, після нього комітів у `Persistence` немає). Три зони вище лишаються авторськи важкими. Паспорт знімає з них залежність від усної пам'яті про межі системи і не замінює парне рев'ю наступної зміни схеми, маршруту або моделі.
