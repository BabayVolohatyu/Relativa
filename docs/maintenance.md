# Регламент супроводу документації

Правило, без якого решта таблиці не працює: зміна коду = зміна документації. Злиття в `main` не приймається, якщо коміт змінює поведінку, контракт або порядок розгортання і не чіпає документ, який цю поведінку описує.

Що оновлювати разом із кодом:

- користувацька поведінка або швидкий старт — `README.md`
- новий або змінений компонент, контракт, модель — `docs/sdd.md`
- порядок сервісів, змінні, CI, RTO/RPO — `docs/isd.md`
- нове архітектурне рішення — новий файл у `docs/architecture/adr/`. Старий ADR не редагується «як насправді ми думали». Йому ставлять статус `Superseded` і дають посилання на новий номер

Власник у таблиці — автор, який відповідає за наступний перегляд. Цикл узятий із порогів аудиту ЛР10: експлуатаційний документ не рідше ніж раз на 90 днів, архітектурний — раз на 180 днів. Дата нижче — день, коли паспорт звірений із кодом гілки `testing/lab10`.

| Документ | Власник | Цикл перегляду | Дата останнього перегляду |
|---|---|---|---|
| `README.md` | Babay | 90 днів, експлуатаційний | 2026-11-22 |
| `docs/sdd.md` | Babay | 180 днів, архітектурний | 2026-11-22 |
| `docs/isd.md` | Babay | 90 днів, експлуатаційний | 2026-11-22 |
| `docs/architecture/adr/0001-shared-postgresql.md` | Babay | 180 днів, архітектурний | 2026-11-22 |
| `docs/architecture/adr/0002-asynchronous-messaging.md` | Babay | 180 днів, архітектурний | 2026-11-22 |
| `docs/audience-matrix.md` | Babay | 90 днів, разом із README | 2026-11-22 |

Перегляд означає звірку з кодом, а не зміну дати. Якщо код за цикл не змінював контракт, дата все одно зсувається, і в коміті є примітка «звірено, розбіжностей немає».

Повторний перегляд після краш-тесту Documentation Decay: 2026-11-22. Звірено контракт `GET /api/v1/operator/digest` і залежність Graph від старту контейнера ML. Розбіжностей із кодом після відновлення немає.
