# ADR 0002. Події через транзакційний outbox і RabbitMQ

- Статус: Accepted
- Дата запису: 2026-11-22
- Рішення вже працює: Authentication і Core пишуть `audit_outbox`, Audit, Graph і ML читають обміни. Наступна зміна транспорту отримає новий номер. Цей запис заднім числом не редагується.

## Контекст

Після зміни угоди мають статися три речі, і жодна не повинна відкотити саму угоду, якщо сусід повільний: рядок журналу, оновлення графа в браузері, перерахунок оцінки ML. Прямий HTTP із Core у Graph і Audit зв'язав би доступність угоди з доступністю читачів.

## Розглянуті альтернативи

1. Синхронний HTTP між сервісами. Відхилено для цих трьох ефектів: таймаут ML або Audit заважав би зберегти угоду. У коді й досі немає службового HTTP між бекендами.
2. Сервісна шина іншого виробника або Kafka. Відхилено на розмірі команди і стека: RabbitMQ 3.13 уже в Compose, обсяг подій — рядки CRM, не потік телеметрії.
3. Запис журналу тим самим процесом Core у таблиці аудиту, без черги. Відхилено: Audit тоді не є окремим писарем, а Graph і ML усе одно потребують сповіщення.

## Рішення

Зміна даних і рядок `audit_outbox` комітяться однією транзакцією PostgreSQL. Диспетчер публікує payload у RabbitMQ. Обмін `audit.events` (ключ `audit.#`, черга `audit.events.audit`) читає Audit. Обмін `relativa.domain` читають Graph і ML. Оцінка на запит графа йде окремим RPC `relativa.graph_ml`: це теж AMQP, не HTTP, і відсутня відповідь не скасовує угоду. Споживачі гасять повтори (`audit_processed_event`, `rabbitmq_processed_delivery`).

## Наслідки

- Збереження угоди не залежить від того, чи живий у цю секунду процес ML.
- Подія може дійти двічі. Споживач зобов'язаний бути ідемпотентним. Це частина контракту, не оптимізація.
- Брокер без тома в Compose втрачає непідтверджені повідомлення. Відновлення йде з outbox у базі, див. [ISD](../../isd.md#rto-і-rpo).
- Новий споживач підписується на обмін. Новий синхронний виклик між сервісами потребує нового ADR, а не ще одного `HttpClient` у Core.
- Операційні команди черг лишаються в [runbook](../../runbooks/RABBITMQ-CHOREOGRAPHY.md), щоб цей запис не розпухав процедурами.
