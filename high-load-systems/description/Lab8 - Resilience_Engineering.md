# **ЛАБОРАТОРНА РОБОТА № 8 Тема: Інженерія стійкості (Resilience Engineering): Захист від Cache Stampede, Thundering Herd та Cache Penetration** 

#### **1. Мета роботи** 

На основі відмовостійкої розподіленої системи (Лабораторні роботи № 1–7) дослідити поведінку кешованого шару читання при масовому конкурентному зверненні клієнтів у моменти відсутності даних в кеші (Cache Miss / Cache Expiration). Відтворити ефекти **Cache Stampede** та **Thundering Herd** , кількісно оцінити деградацію шару СУБД та розробити механізми координації запитів (Request Coalescing, Distributed Lock, Mutex/Single-flight, Stale-While-Revalidate) і захисту від фатальних атак (Negative Caching / Bloom Filters). 

По завершенню роботи студенти повинні вміти: 

- моделювати та експериментально відтворювати феномени лавинного навантаження (Cache Stampede, Thundering Herd, Cache Avalanche); 

- реалізовувати захисні паттерни координації запитів (Single-flight / Request Coalescing / Distributed Locks) для одноразового виконання коштовних обчислень; 

- застосовувати ймовірнісні та часові оптимізації політик вичищення (TTL Jitter, Randomized Expiration, Early Background Refresh); 

- розробляти механізми захисту від запитів до неіснуючих сутностей (Cache Penetration) за допомогою Negative Caching; 

- аналізувати компроміси (Trade-offs) та нові точки відмови (Failure Modes) впроваджених механізмів координації. 

## **2. Завдання та етапи виконання** 

### **2.1. Селекція ресурсоємного кешованого об'єкта** 

Обрати популярний і коштовний за обчисленнями read-сценарій (наприклад, агрегована статистика, профіль популярного об'єкта/продукту, глобальний лідерборд), що використовує Redis/Memcached. Обґрунтувати потенційну критичність цього ресурсу у випадку Cache Miss. 

### **2.2. Експериментальне відтворення Cache Stampede & Thundering Herd** 

1. Створити контрольовані умови холодної відсутності ключа (Force Expire / Key Invalidation). 

2. Подати високий рівень конкурентного навантаження (наприклад, 500+ одночасних Virtual Users через k6/Locust). 

3. Зафіксувати сплеск навантаження на Primary/Replica СУБД (Thundering Herd) до моменту збереження ключа в кеш. 

### **2.3. Моделювання лавинного вигасання (Cache Avalanche / TTL Synchronization)** 

Створити сценарій синхронного завершення TTL для групи пов'язаних або популярних ключів. Продемонструвати сплеск затримок та утилізації ресурсів СУБД у момент одночасного занепаду кешу. 

### **2.4. Реалізація механізмів координації та регенерації кешу** 

Впровадити один із професійних механізмів запобігання дубльованим запитам до СУБД: 

- **Distributed Mutex / Lock (Redis Redlock/SETNX):** лише перший запит отримує блокування, звертається до СУБД та оновлює кеш; інші запити чекають розблокування або повторно зчитують кеш. 

- **Single-Flight / Request Coalescing:** групування однакових паралельних запитів на рівні екземпляра сервісу для єдиного звернення до БД. 

- **Stale-While-Revalidate (SWR) / Asynchronous Refresh:** повернення застарілого кешованого значення з паралельним фоновим оновленням. 

### **2.5. Захист від синхронного Expiration (TTL Jittering)** 

Реалізувати рандомізацію часу життя ключів (TTL = Base_TTL ± Random_Jitter) для запобігання синхронним сплескам усунення даних із кешу. 

### **2.6. Захист від Cache Penetration (Negative Caching)** 

1. Створити потік запитів до неіснуючих ідентифікаторів (наприклад, GET /entity/9999999), які пробивають кеш і звертаються до СУБД. 

2. Реалізувати захист через **Negative Caching** (збереження null/порожнього об'єкта з коротким TTL) або перевірку через **Bloom Filter**.

## **4. Порядок захисту та критерії оцінювання** 

### **Процедура захисту:** 

1. **Live-демонстрація Cache Stampede:** Очищення ключа та одночасний запуск 500+ запитів із показом масового звернення до СУБД. 

2. **Live-демонстрація захисту:** Повторний тест із увімкненим Distributed Lock / Singleflight та доведення зменшення звернень до СУБД до 1. 

3. **Демонстрація Negative Caching:** Запити до відсутніх об'єктів та показ захисту СУБД від проникнення. 

4. **Теоретичний захист:** Пояснення різниці між Cache Stampede, Thundering Herd, Cache Avalanche та Cache Penetration; аналіз алгоритмів Redlock, Bloom Filters, Probabilistic Early Expiration (XFetch algorithm). 

### **Критерії оцінювання:** 

- **Практична відтворюваність:** Наочне відтворення та усунення проблеми в реальному часі. 

- **Якість реалізації захисту:** Відсутність дDeadlocks та коректна обробка TTL/Timeouts у блокуваннях. 

- **Глибина розуміння trade-offs:** Чітке усвідомлення обмежень та нових ризиків обраного захисного паттерну.
