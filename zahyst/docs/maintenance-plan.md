# План супроводу

Замикає книгу аудиту: хто відповідає вночі, куди ескалувати і що в Migration ще не закрито. Регламент віку документів лишається в [maintenance.md](maintenance.md). Числа SLO — лише в [slo.yaml](https://github.com/BabayVolohatyu/Relativa/blob/testing/lab12/docs/slo.yaml). Команди дампа — лише в [RB-001](runbooks/RB-001.md).

## Лінії

| Лінія | Бере | Віддає далі |
|---|---|---|
| L1 | Перевіряє `GET /health`, дивиться, чи контейнер `relativa-postgres` running, чи є файл у `backups/` | Якщо health не `ok` довше 10 хвилин, або BackupStale, або postgres не стартує |
| L2 | Migration, шлюз, розбір логу `pg_restore` і коду виходу контейнера `migration` | Якщо треба міняти схему, гарду truncate або том уже втрачено |
| L3 | ISD, ADR-0001, рішення відновлювати основну базу з дампа | Ескалація за межі команди не описана: продакшен-майданчика в репозиторії немає |

L1 не читає C# і не виконує `DROP DATABASE`. L2 не публікує новий RPO без drill. L3 не погоджує нормальну зміну під change freeze з протоколу CCB.

## Матриця ескалації

| Серйозність | Реакція | Кому | Канал |
|---|---|---|---|
| SEV-3, один стенд, дані на томі, дамп свіжий | 1 робочий день | L1 | issue в репозиторії |
| SEV-2, BackupStale або postgres недоступний, том на місці | 30 хвилин | L2, власник RB-001 | issue і повідомлення власнику `docs/runbooks/RB-001.md` |
| SEV-1, тома немає і свіжого дампа немає, або `migration` падає і стек не піднімається | 15 хвилин | L3, власник ISD | issue з міткою SEV-1. CCB для термінової зміни збирається тим самим днем |

Час реакції — до першої дії з runbook, не до повного RTO. RTO 4 години лишається ціллю відновлення, не ціллю першої відповіді.

## Відомі проблеми

| ID | Обхід |
|---|---|
| Немає копії поза машиною | Не вважати RPO виконаним. Не запускати `docker compose down -v`, доки не знято дамп і він не скопійований на інший диск |
| Немає щоденного розкладу дампа | Поки що запуск `ops/pg-dump.ps1` руками. `ops/check-backup-age.ps1` показує, що доба прострочена |
| RabbitMQ без тома | Після перестворення брокера непідтверджене повідомлення зникає. Повтор лежить в outbox бази. Runbook черги — [RABBITMQ-CHOREOGRAPHY](runbooks/RABBITMQ-CHOREOGRAPHY.md) |
| README Migration суперечить коду | Не користуватися ним. Карта компонента — [legacy-migration](operations/legacy-migration.md) |
| Down-міграції EF немає | Відкат схеми — дамп, не `Migrate` назад |

## Що робити з боргом Migration далі

1. MIG-D2 і MIG-D3 закриті CAPA-001 і CAPA-002. Повторювати drill після кожної зміни `entrypoint.sh`.
2. MIG-D1: README лишається deprecated. Новий текст туди не пишеться, щоб не було двох інструкцій.
3. MIG-D4: down-міграція окремим RFC, не цим планом. До того відкат даних лише дампом.
4. Наступна нормальна зміна інфраструктури не закривається без рядка drill у release checklist.
